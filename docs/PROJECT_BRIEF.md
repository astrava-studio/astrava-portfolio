# ASTRAVA Portfolio — Project Brief

## 1. Purpose

Build the public website for ASTRAVA, an independent three-person digital studio. The website should communicate what the studio does, demonstrate its work, establish trust through clarity and quality, and make it easy for potential clients to start a conversation.

## 2. Audience

- Small and medium-sized businesses
- Founders and individuals who need a website or digital product
- Local businesses exploring digital improvements
- Potential collaborators

## 3. Positioning

**Working headline:** Ideas into digital experiences.

**Supporting direction:** ASTRAVA designs and builds thoughtful websites and software solutions that help businesses turn ideas into useful digital experiences.

Keep public claims aligned with the team's actual skills and delivery capacity.

## 4. Initial page structure

1. Navigation — wordmark, section links, contact call to action
2. Hero — positioning statement and primary actions
3. Selected work — demonstration projects and other finished work
4. Services — only services the team can currently deliver
5. About — an honest introduction to the independent three-person studio
6. Process — Discover, Plan, Design, Build, Deliver
7. Contact — a working enquiry path
8. Footer — navigation and approved contact/social links

## 5. Project showcase rules

Each project entry should support:

- Name and short description
- Category
- Technology stack, once confirmed
- Cover image
- Project status (concept, in progress, or completed)
- Live URL, only when deployed and verified
- Source URL, only when intentionally public

Keep project data separate from presentation components so entries can later be added, edited, removed, and reordered without rewriting the cards. Any private content-management interface must be protected and excluded from public navigation.

## 6. Visual direction

- Overall feel: premium, minimal, modern creative-tech
- Palette direction: charcoal, warm white, electric blue accent
- Typography: clear, contemporary sans-serif
- Layout: strong hierarchy, generous spacing, deliberate composition
- Motion: restrained and purposeful, with reduced-motion support

Exact colors, typefaces, layout details, and motion behavior will be decided during design.

## 7. Functional requirements

- Responsive navigation
- Working project links
- Functional contact method (configured email, WhatsApp, or a real form provider)
- Accessible focus and hover states
- Semantic page structure
- Page title, description, social preview metadata, and favicon
- No placeholder controls that pretend to work

## 8. Non-goals for the first release

- Building a full CMS from scratch
- Visitor user accounts
- Complex backend services
- E-commerce
- Claims or case studies unsupported by real work

## 9. Acceptance criteria

The first release is ready when:

- Main sections are complete and coherent.
- Layout works on mobile, tablet, and desktop.
- All visible links and controls work.
- Contact enquiries reach the configured destination.
- Project statuses and claims are accurate.
- Accessibility and reduced-motion basics are addressed.
- Production build succeeds.
- Deployment and update instructions are documented.
